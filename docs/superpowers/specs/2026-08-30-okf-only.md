# Job Seeker Skill: one source, compiled

**Supersedes** `2026-08-29-ujd-ugs-tailoring-design.md`, which this measures rather than rejects. That
design's shape — gaps close before the resume is written — is kept intact. What changed is who builds
the documents it runs on.

## Problem

The first production run of the 08-29 design, session `be22a375`, tailoring one posting:

| | measured |
|---|---|
| Wall clock | 117 min |
| Subagents running | 63 min, eight of them, near-sequential |
| Scripts | 3 min |
| Waiting on the person | 34 min |
| Intermediate JSON written | 158 KB |
| **What was actually decided** | **2.8 KB** — a view with four entries, and one narrative |

Three findings, each traceable to one cause.

**Every consumer of UJD and UGS was circular.** `validate_ujd.py`, `validate_ugs.py` and
`migrate_bundle.py` read them; the four agents wrote them. The only non-circular reader was
`score_projects.py`, which needs eight flat fields — about 2 KB of the posting's 57 KB. `pipeline.py`,
the cross-application tracker, reads Markdown frontmatter and never touched the JSON layer at all.

**`record.json` was a model's transcription of data the bundle already held.** A twenty-line prototype
compiled the same fifteen projects straight from frontmatter, matching every title. The
`achievements/metrics.md` table held seventeen verified metrics; the transcription had carried ten.
Two of the record's four organizations had **no concept behind them** — invented during transcription,
and on the resume.

**The formal machinery was unused.** `score.aggregate` was computed, weighted, re-derived by its
validator, and read by nothing. `requirement_groups`: zero in a real posting. `span[]`: 8.5 KB of text
copied out of files in the same directory. `jsk-posting-analyst` spent seven of its fourteen minutes
grepping `ujd-v1.schema.json` to discover the shape of its own output, and 62 seconds sleep-polling for
a sibling agent's file.

## The shape

```
concepts (Markdown)  ── okf_compile ──►  the record, in memory, < 1s
posting.md           ── frontmatter ──►  requirements the scorer runs on
      └─ analyst ──► gaps.md ──► the person answers ──► concepts ──► recompile
                                          └─ author ──► view.md ──► render ──► gates
```

**The bundle is the only thing anyone edits.** Everything else is built from it.

### Decisions

**The record is compiled, never stored.** `okf_compile.load()` returns the dict `urs/resolve.py`
already took. No file, so nothing to drift, and `--dump-record` exists only for reading.

**The relational spine moves into frontmatter.** A role declares `organisation`, `start`, `end`,
`state`, `seniority` and `change`; a project declares `role`. It was already written down in the
career-progression ladder — just nowhere a compile could read it — so `migrate_bundle.py` fills it in
from there and names every role it cannot place. Bundle revision 5.

**Two things stay authored, and live in the concept they belong to.** A project's `# Bullets` and a
Skill Set's `# Skills`. Naming a competency "C# / .NET" and deciding ASP.NET Core is an alias of it is
editorial judgement; a bullet is prose. Both compound: written once, reusable by the next application.

**The posting is Markdown again.** Revision 4 was right that frontmatter could not distinguish a
demanded requirement from a preferred one. That is one key per requirement, not a 57 KB document.

**Archives are frozen and stay readable.** `validate_ujd.py`, `validate_ugs.py`, their schemas and
`migrate_bundle.py` all remain. Nothing new is written in those formats.

## What the schemas were doing, and what replaced it

`validate_urs.py` enforced eight invariant families. Exactly one was schema-driven. The other seven are
hand-written Python over a dict and were untouched by this change:

ids unique · periods coherent · references resolve · views have a profile · **every numeral traces to a
metric** · **provenance status present** · no bracketed placeholders

Two things did need deliberate replacement:

- **Unknown keys.** `additionalProperties: false` was rejecting `startDate` for `start` — a typo that
  loses a date with nobody noticing. That is now a hand-written check, and it fails rather than warns.
- **Shape drift in the compiler.** A schema asserted the record matched a description of itself. What
  replaced it is a test that compiles a bundle and *renders* it, which asserts the thing that consumes
  it works — the only claim anyone needed. It caught two real shape errors within a minute of existing.

Conformance levels are gone with the transcription they measured.

## Outcome

| | before | after |
|---|---|---|
| Agent invocations per run | 8 | 2 |
| Generated documents | 158 KB | ~7 KB |
| Formats a person can write | 3 JSON + Markdown | Markdown |
| Validator lines in the live path | ~2,500 | ~900 |
| Tests | 462 | 473 |

The anti-invention guarantee is unchanged, because it never lived in UJD or UGS: the view references
ids, authored prose arrives `inferred`, `provenance_floor: confirmed` refuses to render it, every
numeral traces to a metric, and every clause is read back for confirm-correct-or-cut.

It is stronger in one place. `status: confirmed` is now read mechanically from the concept a person
wrote, instead of being re-asserted by a model copying it across.
