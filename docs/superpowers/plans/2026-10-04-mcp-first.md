# MCP first: every everyday action is a tool, and the CLI keeps only the rescue verbs

Date: 2026-10-04. Branch `feat/graph-native-mcp`, still unreleased as 6.0.0. It follows
`2026-10-04-retire-duplicated-cli.md`, which retired the eleven verbs the tools already
duplicated.

## The decision

The person asked whether jsk can be MCP-only (2026-10-04). It cannot be entirely: four commands have
to work when the server cannot start, or when no Claude session is running. Everything else becomes a
tool, and its CLI form exits 2 naming it.

| Stays CLI | Why no tool can do its job |
|---|---|
| `jsk mcp` | something has to start the server: `plugin.json` runs it |
| `jsk doctor` | it diagnoses a missing or broken `mcp` or pyoxigraph, which stops the server from starting. `mcp` 1.4.1 did exactly this on 2026-10-03, and only a shell command could say why |
| `jsk kb new` | it makes the workspace the server serves, at a path the person chooses. A tool would make it wherever the server happened to start |
| `jsk kb load`, `jsk kb dump` | backup and restore without a working plugin, server or Claude session. The restore point taken before the 22 file-made applications were dropped was a `kb dump` |

| Moves to a tool | Replacement | Who calls it now |
|---|---|---|
| `jsk kb check` | `career_check` | auditor, mode-refresh |
| `jsk kb pack` | `career_pack` | mode-refresh |
| `jsk kb merge` | `career_merge` | auditor, mode-refresh |
| `jsk resume check` | `resume_check` | verifier, auditor, mode-resume/tailor/ship |
| `jsk resume render` | `resume_render` | mode-resume, templates.md |
| `jsk resume preview` | `resume_preview` | templates.md, SKILL.md |
| `jsk resume fit` | `resume_fit` | verifier, mode-ship |
| `jsk resume ship` | `resume_ship` (exists) | verifier, mode-resume/setup |
| `jsk app drop` | `app_drop` | mode-refresh, mode-tailor |

## P0: can a tool take this long? (done, 2026-10-04)

These verbs were timed on a scratch copy of the real workspace (`C:\Projects\basilin-joe-resume`),
for the graph-native Wolters Kluwer application:

| Verb | Time |
|---|---|
| `resume check <stem>` | 1.4 s |
| `resume render --pdf` | 2.8 s |
| `resume preview` (six templates) | 4.6 s |
| `resume fit --target-pages 2` | 11.9 s |
| `resume ship` | 21.4 s |
| `kb check` | 0.7 s |
| `kb dump` | 0.5 s |

The longest, `ship`, is already the `resume_ship` tool, so a new tool adds no call longer than one the
server already makes. What P0 could not show is Claude Code's own limit on an MCP call. P6 runs
`resume_ship` from a live Claude Code session. If that call times out, the mode files name
`MCP_TOOL_TIMEOUT`, and nothing else changes.

## Rulings

1. **It goes into 6.0.0.** Nothing is tagged, so as in the last plan there is no released version to
   warn from first.
2. **The tools.** Each one takes, as named arguments, the flags its CLI form took. Each returns the
   server's usual shape (`ok`, `findings`, data).
   - `career_check()`: the workspace's FAILs and WARNs, each with its fix, and the unsent file-made
     applications (`application/timeline/unsent.py`). It writes nothing.
   - `career_pack(pack)` and `career_merge(concept, into)`: the drafted changeset as text in
     `changeset`, ready for `career_preview`. They write nothing and no file, so `--out` goes, and
     so does the draft file mode-refresh used to pass between commands.
   - `resume_check(target=None, path=None, record=None, only=None, strict=False)`: exactly one of
     `target` (the record gate) or `path` (a PDF, a .tex or a render directory: the parse, prose and
     layout gates).
   - `resume_render(target, out=None, pdf=False, ...)`, `resume_preview(target, out)` and
     `resume_fit(tex, target_pages)`: the paths each one wrote. The verifier and the main session open
     a PDF or PNG with Read, as they do today.
   - `app_drop(app, reason=None, dry_run=False)`: what it removed and where the folder went.
   - Each gate's verdict line (`PASS - safe to send`, `DO NOT SEND`, ...) is carried word for word in
     a `verdict` field. Tests pin that text, and a tool must not reword it.
   - `writes=True` only where the compose function writes the store. A render writes files, not the
     record.
   - New tools go in new modules (`adapters/mcp/rendering.py` for the resume_* tools - `resumes`
     is already server.py's registration of resume_select/update/ship - and
     `adapters/mcp/upkeep.py` for career_check/pack/merge and app_drop). `server.py` is at 511 of
     `test_sizes`' 600 lines, and the last tools to overflow went to `acts.py` the same way. Each module
     gets its line in ARCHITECTURE.md.
3. **Grants follow the work, and Bash leaves the agents.**
   - Verifier: `Read`, `Glob`, `resume_check`, `resume_fit`, `resume_ship`, `career_show`, `app_show`.
     It no longer has Bash.
   - Auditor: its tools plus `career_check` and `career_merge`. It no longer has Bash. It drafts a
     merge and never applies one, as now.
   - `app_drop` is destructive, so, like `career_confirm`, no agent is granted it. The main session
     reaches it through the `mcp__plugin_jsk_graph__*` wildcard after the person agrees.
   - `test_agent_grants.py` pins each list, and the agent-boundary sentences stay.
4. **Each retired verb exits 2, names its tool, and writes nothing**, through the mechanism already in
   `main.py`.
   - `kb check`, `kb pack` and `kb merge` get `"<noun> <verb>"` entries in `RETIRED`.
   - `resume` and `app` have no verbs left, so they go into `RETIRED_NOUNS`, each verb with its own
     entry.
   - The old top-level entries that point at a verb now retired (`validate`, `check`,
     `check --only letter`, `gates`, `render`, `preview`, `fit`, `ship`) become plain strings naming
     the tool. `new` still points at `jsk kb new`.
   - `jsk --help` lists `doctor`, `kb new|load|dump` and `mcp`, then says that everything else is a
     tool.
5. **Only the front ends go; the gate pipeline stays.**
   - `resume_ship` and `check DIR` run the gates in-process by calling each gate module's
     `main(argv)` through `dispatch.call_gate` (`gates/check.py`, `ship.py`). Those modules are
     internal API, and they stay. So do tests that drive them with a documented script name
     (`fixtures.run("check_ats.py", ...)`).
   - The modules that go:
     - `adapters/cli/resume.py`
     - `adapters/cli/drop.py`
     - the argv parsing in `kb/read.py` (`cmd_check`) and `kb/draft.py`
     - `main.py`'s `resume_check`, `resume_ship`, `app_drop` and `NOUN_USAGE`
     - `render.py`, `preview.py` and `fit.py`, but only if nothing but dispatch reaches their `main`
   - Rule for each module: it stays only if a tool or the ship pipeline reaches it. P1 lists what it
     kept and why.
   - **Amended before P1 (2026-10-04):** the tools call the entry points the commands called, through
     `adapters/mcp/captured.py` (`ran` for a documented script name through `dispatch.call_gate`,
     `called` for `resume.cmd_resume_check` and `drop.main`, both run inside the workspace).
     - So the argv entry points (`render.py`, `preview.py`, `fit.py`, `resume.py`, `drop.py`,
       `kb/read.py`'s `cmd_check`, `kb/draft.py`) stay, as internal API, the way `resume_ship`
       already used `render.rendered` and `fit.fitted`. Only `main.py`'s dispatch rows, its
       `resume_check`/`resume_ship`/`app_drop` wrappers and `NOUN_USAGE` go.
     - Why: every verdict line stays byte for byte the text the tests pin, no second reading of the
       flags can drift from the first, and the test conversion is a change of entry point, not of
       assertion. Turning those argv parsers into keyword functions is a refactor of its own, with
       no behaviour in it, and it is not in this plan.
     - Each kept module's docstring and usage text stop saying `jsk resume ...` as current and name
       the tool that calls it.
   - **The tool-list budget rises.** `test_budget.TheToolDefinitions` held 21 definitions under 3,800
     (3,463 measured). Eight more, each about 125, come to about 4,500. The cap goes to the measured
     size plus about 200, written down beside the measurement as the last two raises were, and the
     count goes to 29.
6. **Shared code moves out from under `cli/`** (P4, after the behaviour has moved).
   - Today the MCP server imports `..cli.compose`, `..cli.gates` and `..cli.presenters`. With three
     CLI verbs left, the path `cli/` no longer describes that code.
   - New locations:
     - `adapters/cli/compose/` becomes `adapters/compose/`, still the one composition root.
     - `adapters/cli/gates/` and `dispatch.call_gate`'s gate-running half become `adapters/gates/`.
     - `presenters.py` goes with whichever side still uses it.
     - `adapters/cli/` keeps `main.py`, `doctor.py`, `kb/` (new, load, dump), `cliutil.py` and
       dispatch's verb half.
   - **Settled before P4 (2026-10-04)**, after P1-P3 showed where the code is used. Three
     packages:
     - `adapters/compose/`: the composition root (`adapters/cli/compose/` moved), bound by both
       doors.
     - `adapters/entry/`: the argv entry points both doors run. `gates/`, `kb/`, `render.py`,
       `preview.py`, `fit.py`, `resume.py`, `ship.py`, `drop.py`, `presenters.py` and
       `cliutil.py` move there, and so does `dispatch.py` whole. Its script-name index and
       `call_gate` are how both doors reach an entry point, and its `run_in_process` and
       `workspace_refusal` are a few lines that `cli/main.py` imports from it. "Entry point" is
       the word P1-P3's docstrings already use.
     - `adapters/cli/`: `main.py` and `doctor.py` - the `jsk` command and nothing else.
     - `cli/` and `entry/` sit at the same depth, so their imports of the inner rings keep their
       dots. `compose/` moves up one level, so its imports lose one.
   - It is a move, not a rewrite. Each symbol is moved with LSP `findReferences`, including lazy
     imports. `test_layers.py` keeps passing because it is the same ring.
   - CLAUDE.md's "composition root" sentence and ARCHITECTURE.md's layout follow the move.
7. **`jsk.cli` keeps only what `main_console` needs.** It re-exports about thirty names "callers and
   tests reach through it". Tests import from the real module instead. The console entry point and
   the old-launcher promise (Ruling 4 of the onion design) stay.
8. **Tests move to the layer that remains, as in the last plan's Ruling 6.**
   - A test of a retired verb's behaviour calls what the tool calls, through `tests/recordkit.py`,
     extended. It still returns `(exit code, output)`, so assertions on text carry over.
   - Each new tool gets `test_mcp_*` cases for its JSON shape, plus its refusal on an unloaded
     workspace.
   - Tests of a retired verb's flag parsing or `--help` go. A `test_retired.py` case replaces them:
     exit 2, the tool named, the store unchanged.
   - No test is weakened to pass.
9. **The repo is left clean, and the sweep is part of the work** (P5).
   - Run `vulture src tests --min-confidence 60` (installed only to run it, not added as a
     dependency). Triage every hit. These kinds are known to be in use:
     - decorator-registered tools and queries;
     - port Protocols that docstrings cite;
     - `HTMLParser` overrides;
     - generated test names (`fires`, `passes`, `splits_none`);
     - `unittest` classes.
   - Everything else is deleted.
   - These go:
     - tests whose subject is gone;
     - kit helpers that nothing calls;
     - committed fixture directories that nothing reads;
     - prose that names a retired verb as current. Retirement history in docstrings stays: it is how
       the standards say a module names what it replaced.
   - Every bullet under 6.0.0 in `README.md`, and `docs/SCRIPTS.md`'s retired table, lists the new
     retirements.
10. **The prose follows.**
    - `SKILL.md`, the mode files, the agents, `templates.md`, `rationale.md`, `ats-rules.md` and
      `resume-format.md` name tools.
    - `mode-setup` keeps `jsk doctor`, `jsk kb new`, `jsk kb load` and `jsk kb dump` through the main
      session's Bash.
    - `docs/SCRIPTS.md`, ARCHITECTURE.md, QUICKSTART.md, README.md and CLAUDE.md follow. In CLAUDE.md
      that covers the "CLI dispatch is in-process" paragraph and its `jsk resume ship` example.
    - `test_plugin_surface.py` (every dispatched subcommand named) and `test_budget.py` still hold.

## Phases

Implementation goes to Sonnet subagents with self-contained prompts. Review, plan changes and debugging
stay in the main session. Nothing is committed while an agent is working.

- **P1, tools (one agent):** Rulings 2, 4 and 5 under `src/`.
  - Write the new tool modules, the `test_mcp_*` cases, the `RETIRED` entries and the `test_retired.py`
    cases. Delete the front ends.
  - Run the suite and list the failures by file.
  - Report each module kept under Ruling 5, and why. Do not commit.
- **P2, tests (two agents, disjoint files), alongside P3:** convert the failures under Ruling 8.
  - Agent A takes `test_resume_*`, `test_render_*`, `test_fit_*`, `test_grammar.py` and
    `test_record_gate.py`.
  - Agent B takes everything else.
  - Neither touches `test_plugin_surface.py`, `test_budget.py` or `test_agent_grants.py`.
- **P3, prose and grants (one agent, alongside P2):** Rulings 3 and 10, with the three pinned tests
  above.
- **Commit P1 to P3** after a full suite run, ruff and pyright.
- **P4, the move (one agent, LSP loaded first):** Rulings 6 and 7.
  - Run the full suite before it commits.
- **P5, the sweep (main session, one agent for the deleting):** Ruling 9. The main session triages the
  vulture list, and the agent deletes what was triaged.
- **P6, verify:**
  - Full suite, ruff, pyright, and the budget test run alone.
  - A code review of the diff.
  - A replay on a scratch copy of the real workspace:
    - each retired verb exits 2 and the store's revision does not move;
    - each new tool answers through an in-memory MCP client;
    - `career_pack`'s text goes through `career_preview` and `career_apply`;
    - `resume_render` and `resume_fit` write their files, and `resume_check` on that directory
      passes.
  - A live Claude Code session calls `resume_ship` (the P0 timeout question) and `career_check`.
  - Reinstall the plugin and the global `jsk`.

## Status

- P0: done. The timings are above.
- P1 (tools), P2 (tests) and P3 (prose and grants): done. Opus made the calls, and Sonnet agents
  wrote the code in two parallel rounds, each owning disjoint files. The main session built the
  shared foundation (`captured.py`, the empty modules, the `tests/fixtures.py` seam) and reviewed
  each hand-back.
  - `captured.answered`'s `verdict` is the last verdict line (`PASS - `, `FAIL - `, `DO NOT `,
    `verdict: `), not the last line printed. The parse gate and the fit print advice after their
    verdict, and a caller reading `verdict` would have taken the advice for it.
  - `findings_in` needed two fixes the agents found: `jsk kb check` indents its findings, and the
    gates' tally line `FAIL 0   WARN 0` is not a finding.
  - `tests/fixtures.py`'s `PARSE_GATE`, `PROSE_GATE`, `RECORD_GATE`, `RENDER` and `FIT` name a
    tool and its flags now. `run()` calls the entry point that tool calls, in process, so about
    150 tests converted with no assertion changed.
  - A regression was caught and fixed: `jsk doctor --verify` spawned `python -m jsk resume
    check|render`, which would have reported BROKEN on every machine. It now spawns the entry
    points the tools call.
  - The retired-name scan (`test_grammar.RetiredNamesAreNotTaught`) holds the commands that
    became tools to src's printed strings and to `plugins/`, the prose an agent runs.
    `README.md`'s 6.0 notes and `docs/SCRIPTS.md`'s retired tables name them as history, as they
    name the verbs retired before them. A planted case pins both halves.
  - Known gap: `jsk resume render --list-templates` has no tool. `references/templates.md` holds
    the catalogue, and `resume_preview` renders every template.
- Before this plan, one cleanup turned up three pieces of dead code, removed in `79d092d`:
  - `match_posting.py`'s `COVER`, `MatchStopped` and `MatchReport`, which the retired `jsk tailor
    match` used;
  - its docstring, which still described that verb as current;
  - three constants in `test_awkward_input.py` that nothing read.
